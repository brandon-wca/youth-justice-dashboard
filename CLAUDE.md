# Rules for Claude in dashboard/

Also read `../CLAUDE.md`: the procedure, the dialogue and the cross-effects apply here. "The user" is whoever is giving the instructions.

## Questions to ask, by scenario

Ask only what the files can't tell you. Show the user the answer you've assumed if the request already implies it.

- **2. Text.** Which passage (quote it back). What should it say instead; if the user has no wording, say "I'll draft it and show you". Why (so the change log says so). Should grammar fixes elsewhere in the same passage be made too (default: yes).
- **3. New indicator or design.** Indicator: which measure; which table and column it comes from; where it goes (map, chart, headline); compared with what (places, years, groups); what the denominator is. Design: what exactly changes, where, and what it should look like (ask for a screenshot or an example). Then say which files the change touches before starting.
- **4. Under construction.** Freeze (site stays as it is) or hide (holding page)? For how long, and who restores it?
- **5. Something failed.** What the user sees, on which page section, in which browser, since when, and what changed last (check `CHANGELOG.md` and the git history yourself first).
- **6. Slow.** Where it's slow (first load, the map, a chart), on what device and connection. Then measure before proposing anything.
- **7. GitHub or Netlify.** What was done last and what the screen says (ask for the exact error text or a screenshot). Read the Netlify deploy log if the problem is publishing.
- **10. Restore.** Restore what (one file, or the whole page) and to when (a date, or "the last version that worked"). Show the candidate commit before restoring.

## Do

- Keep the structure: `index.html` (words), `charts.js` (drawing), `styles.css` (looks), `data/` (generated numbers), `resources/` (libraries and fonts we didn't write).
- Keep every number on the page coming from `data/data.json`: `data-fill` tags in the text, the chart functions in `charts.js`.
- Keep the code readable: plain-language comments, named sections, one function per chart, settings at the top of the file.
- After any change, open the page in a browser at desktop and phone width and fix anything that overflows, overlaps or errors before reporting back. Show screenshots for anything visual.
- Show the old and new text side by side for any wording change before committing.
- Whenever `data/data.json` changes, re-read every heading and commentary claim against the new numbers (the list is in the comment at the top of `index.html`) and report which no longer hold.
- Check any new color for color-blind readers before using it (the palette at the top of `styles.css` has already been checked).
- For a failure (scenario 5), name a cause only with evidence: the error text and what triggers it. Propose the smallest fix. If you can't reach confidence, say so instead of guessing.
- For slowness (scenario 6), measure first and report numbers; propose fixes ranked by gain and risk; change nothing without approval.
- Add a line to `CHANGELOG.md` (date, who, what, why) as part of every change, before committing, naming who asked.
- Stop and ask the user when a request is ambiguous or touches something these rules don't cover. Say what you found and the options; wait for the answer.

## Don't

- Don't edit anything in `data/` by hand. It is generated by `../update_data_here/build_data.py`.
- Don't add libraries, folders, build tools or links to outside sites (fonts, scripts, tiles). Everything the page needs loads from this folder.
- Don't define a color or font anywhere except the top of `styles.css`.
- Don't change what the dashboard says without being asked: which measures, which charts, which places, which denominators. "Kept in criminal court" always leaves out cases the DA declined.
- Don't rewrite the commentary beyond what was asked; it belongs to the user and their team. Grammar fixes yes (unless told not to); new meaning no.
- Don't push, revert or restore anything in git without the user's explicit go-ahead for that specific action.
